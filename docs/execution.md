# Audited SSH execution

SSH is opt-in. Without `POSTERN_EXECUTION_CONFIG` the tool inventory remains exactly `hosts`. With it, the tool inventory is `hosts`, `open_session`, `exec`, `close_session`, `audit`.

The setting names a JSON file with `audit_dir`, `runtime_dir`, and `profiles`. See [the Gont example](../deploy/gont/execution.example.json). Directories must be absolute, private (0700), and non-symlink directories. The parent must exist. Each profile names a host ID already granted in the inventory, a fixed hostname, username, port, absolute private identity file and trusted known-hosts file. Private keys must exclude all group/other permissions. SSH file paths cannot include whitespace or expansion syntax. Populate host keys through an independently trusted channel; do not trust a first network scan.

The service account owns its private audit, runtime and proxy directories. The target SSH user must not be able to read or modify those directories. The Gont test target is `postern-ssh`, a dedicated non-root account with no sudo membership. To switch to an administrator later, provision a separate SSH key and independently reviewed target account, update only the operator profile's `username` and `identity_file`, and restart Postern. An MCP caller cannot request or elevate an account. Changing host grants is applied on the next operation; unreadable/invalid inventory denies execution. The public host response exposes no SSH connection details.

`open_session({"host_id":"gont"})` establishes a pinned, key-authenticated OpenSSH master and returns an opaque session ID plus Unix-second deadlines. Sessions expire after 300 seconds idle or 3600 seconds total and are invalidated on restart. At most 32 sessions/opening connections exist. Expired/revoked sessions are reaped every five seconds. Each session permits one active command; other sessions can run concurrently.

`exec({"session_id":"...","command":"pwd && id","timeout_seconds":10})` accepts arbitrary UTF-8 shell text without classification. Commands are limited to 8192 bytes (no NUL); the timeout is 1..60 seconds, default 10. Each command uses a fresh remote shell over the persistent transport. Working directories and environment changes do not persist between calls. OpenSSH runs through argv without a local shell; ambient SSH config, agents, forwarding and local commands are disabled.

The result contains `record`, `stdout`, `stderr`, and `audit_degraded`. `record` includes IDs, issuer+subject actor, exact command, timestamps, observed outcome, exit status, total output byte counts and truncation flags. Each output retains at most 65536 bytes, decoded with UTF-8 replacement if necessary. Both pipes continue draining past the cap.

Outcomes are `completed` (including non-zero remote exit), `transport_error` (local transport could not run), `timed_out`, `cancelled` (revoked before dispatch), or `unknown`. SSH exit 255 is always unknown because OpenSSH cannot disambiguate a remote exit 255 from transport loss. A timeout kills the local SSH command process; it cannot promise to kill remote descendants or undo side effects. Never automatically retry after response loss.

`close_session({"session_id":"..."})` requires the owning principal and current grant. It revokes immediately. Already dispatched commands drain under their timeout, then release the owned master. Other actors receive the same generic unavailable/denied result as an invalid handle. Restart revokes all handles.

`audit({"command_id":null,"session_id":null,"limit":20,"before":null})` returns only the current issuer+subject's latest command records in reverse event order. The limit is 1..100. Pass `next_cursor` as `before` to page older records. There is no cross-user administrative API; local filesystem access is the operator's administrative boundary.

SQLite uses WAL and FULL synchronization. Every invocation receives an immutable random ID; accepted and running events commit before command spawn. Startup holds an exclusive writer lock and appends unknown outcomes for unfinished records. If an intent/running write fails, nothing launches. If finalization fails, the response marks `audit_degraded`, observed execution output remains available, and further executions fail until storage is repaired and the service restarts. Audit retains exact commands and outcome metadata, not stdout/stderr bodies. Commands may themselves contain secrets: keep the entire audit directory private and back it up accordingly. Local audit is not tamper-proof against an administrator.

The complete Docker suite runs real SSH with freshly generated pinned host keys in an unpublished namespace. It proves that forced audit insert failure creates no remote side-effect marker. This is not a power-loss or physical-storage durability test.
