# OAuth and public login

Connect an MCP client to `https://leyline.talesfrom.earth/postern` using OAuth with client ID and secret left blank. The example in `config/chatgpt-mcp.example.json` selects automatic client registration. The user confirmed successful connection through the Plugins/MCP management page on 2026-10-30 and subsequently reported execution and actor-scoped audit retrieval.

The deployed path is Caddy → a dedicated FastMCP `OAuthProxy` adapter → Postern's private Unix socket. The adapter reuses the existing Trilium MCP runtime and library rather than implementing an OAuth broker in Rust. Its reproducible configuration lives in the infrastructure repository under `deployed/postern/oauth/`.

The frontend issuer is `https://leyline.talesfrom.earth/postern`. Caddy routes the resource-specific well-known aliases to FastMCP metadata. The adapter supports dynamic registration and client metadata documents, requires S256, and presents a consent form protected against CSRF before redirecting to the existing Heimdall Keycloak realm. Registered client callbacks are validated by the library; the upstream Keycloak callback is the fixed `https://leyline.talesfrom.earth/postern/auth/callback`.

Keycloak uses the dedicated confidential `postern-login` client. Its secret, the adapter signing key, encryption key and Redis state remain on Gont. The existing passkey flow stays in place. Only the configured owner subject is accepted by the public adapter. Tokens must carry the native resource audience, introspection audience and `postern:use` scope. The earlier manual `postern-chatgpt` client remains disabled.

The adapter forwards the current validated upstream Keycloak access token on every backend request. Postern still introspects it at HTTP admission and inside each tool and requires matching subjects. Adapter tokens are not accepted as native backend credentials. The adapter has no SSH key or audit directory mount. Its TCP ports are not published; Caddy connects to a socket inside its private directory. Native TCP remains loopback-only.

The Rust core also provides static RFC 9728 discovery for deployments using a compatible external OAuth server directly. Set `POSTERN_OAUTH_RESOURCE` to a canonical HTTPS resource URL, configure the trusted Keycloak issuer/audience/client/scope, and explicitly enable `POSTERN_PUBLIC_PROXY` for the configured HTTPS Host/origin. Forwarding headers cannot choose the identity or metadata URL. Group access to the backend socket requires an explicit numeric `POSTERN_PROXY_SOCKET_GROUP`; the default is mode 0600.

Verification includes private and public automatic registration, consent/CSRF and S256 redirection tests, exact-runtime adapter tests for token refresh, caller isolation and no execution retries, and user-confirmed login/tool use. Rust/Docker tests independently exercise native discovery and genuine Keycloak introspection. Public connection acceptance does not certify remote execution lifetime; see [execution](execution.md) for the deadline contract and deployment evidence.
